# Compatibility and Semantic Boundaries

Status: CURRENT. This document tracks the compatibility status of tested titles
and runtime subsystems in Nakagawa Recomp. It names every semantic boundary and
tracking issue, following the project's fail-closed policy: unsupported behavior
fails cleanly at a named boundary and is never faked.

## Library sweep scoreboard

`tools/library_sweep.py` can write a title-free machine aggregate while a library run is
in progress and after it completes. `coverage.iso_count` is the discovered input count;
`coverage.recorded_routes` is the number of rows currently represented in the aggregate.
The aggregate reports source identity, budget, coverage, stage, blocker and library-family
counts, plus the progress comparison. It must not contain title names, disc IDs, source
keys, filenames, or individual NIDs. NID family counts use only the
source-backed public vocabulary derived from `tools/nid_corpus.json`; unrecognized input
values are omitted. Every nonzero blocker class from the finite public bring-up schema
vocabulary and the runner's named timeout/error boundaries is included, sorted
deterministically by descending count and then code; an unrecognized code fails closed.
A later run may use an existing title-free aggregate as `--previous-public-output`. That
file is a user-supplied prior progress claim, not cryptographically authenticated: the
runner validates its structure and internal consistency, so use only an aggregate
generated by a trusted prior run. The runner rejects an input with unrecognized issue
numbers, other unrecognized or title-specific fields before comparing it. Issue references
come from the checked-in schema allowlist also used by the public `nk_cli.py` report
generator; no network lookup is involved.

The `ratchet.furthest_stage_high_water` values are high-water counts. They can increase
when the source identity, route budget, and ISO count match the previous aggregate, and
never decrease during that matched comparison. `coverage` and blocker fields describe the
current run and remain diagnostic. If the source identity, route budget, or ISO count
changes, the comparison reports `NEW_BASELINE` and starts a new high-water baseline rather
than merging incomparable results. A run without a supplied previous aggregate reports
`NO_BASELINE`.

The comparison is a title-free progress signal. It does not establish complete commercial
title compatibility, stable in-game input, PSP timing, visual fidelity, or hardware
correctness; those claims require their own qualified evidence.

## Subsystem compatibility

Every subsystem state is derived from maintained engineering contracts and live
GitHub Issues. Where an API or capability is unsupported, Nakagawa Recomp halts
at a named semantic boundary rather than simulating phantom success.

| Subsystem | State | Current capability & boundaries | Tracking issue |
| :--- | :--- | :--- | :--- |
| Graphics / GE | Partially works | SDL3 and Vulkan hardware rendering with software rasterizer fallback present frames and in-game 3D scenes; direct framebuffer presentation is verified by `display-smoke-v1`. A non-finite clip position, projected screen position or lit colour fails its vertex closed on BOTH rasterizer paths: the primitive is dropped and counted (`GESTAT+ ... nonfinite=`, `GEGPU stats: ... nonfinite=`) rather than rasterized from a host `(int)NaN` conversion or handed to the Vulkan clipper as a NaN `gl_Position`, because the PSP GE's own answer for that cell is unmeasured; the two paths share one rule (`ge_vtx_finite`) applied at the capture seam, which also covers the through-mode and patch/spline inputs that carry no upstream per-vertex verdict; the producer of those vertices (an out-of-domain arc-sine argument reaching the bone matrices) is unmeasured too, and a single frame of skinned character geometry can render corrupted at the title-to-main-menu transition, then recovers; its root cause is not established and other titles' skinned models may be affected, with investigation in the works ([#69]); GPU vertex transform & lighting waits for GE correctness and CPU cost measurements ([#318]); real-PSP pixel/command conformance corpus ([#343]) and independent Vulkan re-expression ([#353]) in progress. | [#69](https://github.com/Jstar269/nakagawa-recomp/issues/69), [#318](https://github.com/Jstar269/nakagawa-recomp/issues/318), [#343](https://github.com/Jstar269/nakagawa-recomp/issues/343), [#353](https://github.com/Jstar269/nakagawa-recomp/issues/353) |
