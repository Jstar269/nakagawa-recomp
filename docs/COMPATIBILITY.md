# Compatibility and Semantic Boundaries

Status: CURRENT. This document tracks the compatibility status of tested titles
and runtime subsystems in Nakagawa Recomp. It names every semantic boundary and
tracking issue, following the project's fail-closed policy: unsupported behavior
fails cleanly at a named boundary and is never faked.

## Title compatibility

The table below lists source-owned fixtures, showcase demos, the verified flagship,
and uncatalogued retail discs. Nakagawa Recomp makes no claim of retail title
playability out of the box from an ISO alone ([`ISSUES.md`](../ISSUES.md)).
Uncatalogued discs import as **Experimental** with fail-closed checklists.

| :--- | :--- | :--- | :--- |

Runnable headlessly (`mingw32-make display-smoke-run`) and in the native player (`mingw32-make display-smoke-player`). | [#110](https://github.com/Jstar269/nakagawa-recomp/issues/110), [#297](https://github.com/Jstar269/nakagawa-recomp/issues/297), [#308](https://github.com/Jstar269/nakagawa-recomp/issues/308) |

| PSPDEV Phase 5 Source-Owned Fixture (`pspdev-phase5-v1`) | Boots to a named boundary | Source-owned compiled module built from `fixtures/pspdev_phase5` via PSPDEV/PSPSDK at canonical load base `0x08804000`. | Nakagawa Showcase Demos (`showcase-scene-v1` / TEST00007, `showcase-breakout-v1` / TEST00008) | Partially works | Two project-authored PSP demos (a lit, rotating, textured `sceGu` cube with analog and button input plus `sceAudio` tones, and a Breakout game with score, collision sound effects and a `sceUtilitySavedata` high score) build deterministically with PSPDEV/PSPSDK (`mingw32-make showcase`) and traverse analyzer -> generated AOT -> production runtime -> guest services without private inputs. `mingw32-make showcase-smoke` runs both headlessly and asserts the first-frame checkpoint, the scripted Cross sample, audio-submission telemetry, a non-empty framebuffer, and 3D geometry counters (scene) or a written savedata file (Breakout); the player lists both as bundled library entries. Profile-zero acceptance is still declared `runnable: false` / `scaffold` in `assets/titles/showcase-scene.json` and `assets/titles/showcase-breakout.json`, so runnable profile-zero proof is still open. | [#309](https://github.com/Jstar269/nakagawa-recomp/issues/309) |
| *Hot Shots Tennis: Get a Grip* (UCUS-98701) | Boots to a named boundary | In the public player, the disc is identified from `PSP_GAME/PARAM.SFO` and halts at the fail-closed encrypted executable boundary until the user supplies decrypted modules in `<user data>/titles/UCUS98701/decrypted/` ([#295], PR [#428](https://github.com/Jstar269/nakagawa-recomp/pull/428)). Automated compile-and-launch straight from a raw ISO, with no local title manifest and no developer toolchain, is in the works ([#308](https://github.com/Jstar269/nakagawa-recomp/issues/308)). The private full-build developer route (`nk_manager.ps1 -TitleManifest`) reaches in-game 3D match gameplay with sound, with a known transient model corruption at the main menu ([#69](https://github.com/Jstar269/nakagawa-recomp/issues/69)). | [#69](https://github.com/Jstar269/nakagawa-recomp/issues/69), [#295](https://github.com/Jstar269/nakagawa-recomp/issues/295), [#308](https://github.com/Jstar269/nakagawa-recomp/issues/308) |
| Any other commercial game (Experimental) | Boots to a named boundary | Uncatalogued valid PSP disc images import as **Experimental**. The player parses `PSP_GAME/PARAM.SFO` directly to display title and Disc ID (PR [#426](https://github.com/Jstar269/nakagawa-recomp/pull/426)); the game card notes that compatibility is unknown and shows fail-closed checklist items (encrypted executable boundary pointing to `<user data>/titles/<DISC_ID>/decrypted/`, and PGD-protected content, both [#295](https://github.com/Jstar269/nakagawa-recomp/issues/295)). **BUILD PACKAGE** builds a package for a commercial disc with the public backends and names the remaining limits in the build report (PR [#473](https://github.com/Jstar269/nakagawa-recomp/pull/473)); Play stays disabled until a valid package exists, because an experimental title never launches from a developer runtime (PR [#483](https://github.com/Jstar269/nakagawa-recomp/pull/483)). Generic title intake beyond catalogued titles is in the works ([#285](https://github.com/Jstar269/nakagawa-recomp/issues/285), [#308](https://github.com/Jstar269/nakagawa-recomp/issues/308)). Non-PSP images are refused. | [#285](https://github.com/Jstar269/nakagawa-recomp/issues/285), [#295](https://github.com/Jstar269/nakagawa-recomp/issues/295), [#308](https://github.com/Jstar269/nakagawa-recomp/issues/308) |

## Subsystem compatibility

Every subsystem state is derived from maintained engineering contracts and live
GitHub Issues. Where an API or capability is unsupported, Nakagawa Recomp halts
at a named semantic boundary rather than simulating phantom success.

| Subsystem | State | Current capability & boundaries | Tracking issue |
| :--- | :--- | :--- | :--- |
| Graphics / GE | Partially works | SDL3 and Vulkan hardware rendering with software rasterizer fallback present frames and in-game 3D scenes; direct framebuffer presentation is verified by `display-smoke-v1`. Transient model corruption occurs on main-menu transitions ([#69]); GPU vertex transform & lighting waits for GE correctness and CPU cost measurements ([#318]); real-PSP pixel/command conformance corpus ([#343]) and independent Vulkan re-expression ([#353]) in progress. | [#69](https://github.com/Jstar269/nakagawa-recomp/issues/69), [#318](https://github.com/Jstar269/nakagawa-recomp/issues/318), [#343](https://github.com/Jstar269/nakagawa-recomp/issues/343), [#353](https://github.com/Jstar269/nakagawa-recomp/issues/353) |
| Audio output (SAS / ATRAC3 / Host Audio) | Works | Public builds play sound through the default host audio device via SDL3 ([#301]); runs silently if no device is connected. ATRAC3+ voice lifecycle returns controlled refusal for unsupported formats (`0x80630004`, `0x80630003`) ([#281], [#322]); SAS hardware conformance group planned ([#311]). | [#301](https://github.com/Jstar269/nakagawa-recomp/issues/301), [#311](https://github.com/Jstar269/nakagawa-recomp/issues/311), [#322](https://github.com/Jstar269/nakagawa-recomp/issues/322) |
| Controller input & remapping | Partially works | SDL3 detects connected gamepads and navigates the library. The native Controller Settings screen (`VIEW_CONTROLLER_SETTINGS`) provides interactive button remapping for 14 digital PSP controls + analog stick, conflict detection, deadzone & trigger calibration, a live input monitor, and guided stick and trigger calibration, with atomic persistence (PRs [#455](https://github.com/Jstar269/nakagawa-recomp/pull/455), [#465](https://github.com/Jstar269/nakagawa-recomp/pull/465)); the running game window applies the saved profile (PR [#437](https://github.com/Jstar269/nakagawa-recomp/pull/437)). That profile is one global host mapping in `<user config>/input_profile.json`, overridable per launch with `NK_INPUT_PROFILE` ([#357](https://github.com/Jstar269/nakagawa-recomp/issues/357)). Per-title input profiles are not implemented and no tracking issue is open for them. | [#357](https://github.com/Jstar269/nakagawa-recomp/issues/357) |
| Save data (`sceUtilitySavedata` / Memory Stick) | Partially works | `sceUtilitySavedata` writes and reads save files in a local directory; partial `sceIoDevctl` Memory Stick support for `ms0:` and `fatms0:` provides capacity/cluster geometry. Ordinary `ms0:` file I/O and savedata share one Memory Stick namespace ([#334], done); clean-room savedata lineage replacement planned ([#350]). | [#350](https://github.com/Jstar269/nakagawa-recomp/issues/350) |
| Video / FMV / PSMF (`scePsmf`, `sceMpeg`) | Partially works | Host-HLE PSMF playback (MPEG-4 AVC / H.264 via Media Foundation and standalone decoders) plays video cutscenes in tested titles. PSMF MPEG-PS parser hardening with independent PES/pack fixtures ([#288]); MPEG YCbCr/CSC/PCM HLE semantics validation ([#302]); portable H.264 decoder backend ([#283]); A/V presentation timing reconciliation ([#279]); guest PRX execution for `scePsmf_library.prx` ([#286]). | [#279](https://github.com/Jstar269/nakagawa-recomp/issues/279), [#283](https://github.com/Jstar269/nakagawa-recomp/issues/283), [#286](https://github.com/Jstar269/nakagawa-recomp/issues/286), [#288](https://github.com/Jstar269/nakagawa-recomp/issues/288), [#302](https://github.com/Jstar269/nakagawa-recomp/issues/302) |
| System fonts & Typography (`sceFont`, `libfont.prx`, PGF) | Partially works | Native player UI renders using platform system fonts (or fallback debug text) with zero bundled proprietary fonts. Authentic in-game typography uses user-supplied Sony PSP firmware PGF fonts (`jpn0.pgf`, `ltn0.pgf`) imported with `python tools/nk_cli.py fonts import <folder>` ([#300](https://github.com/Jstar269/nakagawa-recomp/issues/300)); public builds render those PGF files through the project-authored reader `src/rt/pgf_public.c` (PR [#474](https://github.com/Jstar269/nakagawa-recomp/pull/474)). That reader refuses unsupported forms by name, so composite row-order-3 glyphs and the alternate revision/shadow-width variants fail closed rather than render approximately; they are not implemented and have no open tracking issue yet. In the works: refreshing the reader status text and exercising public-converter output through the public APIs ([#510](https://github.com/Jstar269/nakagawa-recomp/issues/510)), the clean-room open-font to PGF converter ([#313](https://github.com/Jstar269/nakagawa-recomp/issues/313)), and guest `libfont.prx` startup without the ready-flag bypass ([#299](https://github.com/Jstar269/nakagawa-recomp/issues/299)). | [#299](https://github.com/Jstar269/nakagawa-recomp/issues/299), [#313](https://github.com/Jstar269/nakagawa-recomp/issues/313), [#510](https://github.com/Jstar269/nakagawa-recomp/issues/510) |
| Networking / WLAN (`sceNet`, `sceNetAdhoc`, `sceNetApctl`) | Not started | All networking APIs are unimplemented. Network module loading via `sceUtilityLoadNetModule` and `sceUtilityUnloadNetModule` returns controlled refusal (`0x80110001` `SCE_ERROR_UTILITY_INVALID_STATUS`). Network sockets, ad-hoc, and infrastructure return unsupported; no networking stubs or fake connections are provided. | [#281](https://github.com/Jstar269/nakagawa-recomp/issues/281), [#307](https://github.com/Jstar269/nakagawa-recomp/issues/307) |
| CPU execution (AOT translation & Interpreter floor) | Works | Two-phase pipeline translates MIPS instructions to portable C chunks (`tools/codegen.py`). Production fail-closed interpreter floor executes valid AOT misses across both CALL and TAIL crossings ([#116], [#127], [#128]). LLE Phase 1 provides COP0 and exception transfer metadata behind opt-in flags. Full authentic LLE exception semantics default ([#321]); INTC interrupt delivery ([#325]); independent reference interpreter ([#345]). | [#116](https://github.com/Jstar269/nakagawa-recomp/issues/116), [#127](https://github.com/Jstar269/nakagawa-recomp/pull/127), [#128](https://github.com/Jstar269/nakagawa-recomp/pull/128), [#321](https://github.com/Jstar269/nakagawa-recomp/issues/321), [#325](https://github.com/Jstar269/nakagawa-recomp/issues/325), [#345](https://github.com/Jstar269/nakagawa-recomp/issues/345) |
| VFPU (Vector Floating Point Unit) | Partially works | Scalar VFPU translation and interpreter covering arithmetic, transforms, and trigonometric operations with hardware-measured bit-exact lookup tables (NaN/Inf quieten settled on PSP-3000 ARK-5 silicon, [#40]). A transcendental argument outside its documented domain is not hardware-measured: the runtime fails closed to the PSP invalid NaN, which is how the main-menu character model corrupts when a title's own rotation math leaves the arc-sine domain ([#69](https://github.com/Jstar269/nakagawa-recomp/issues/69)); measuring that edge on real silicon, plus second-title semantic coverage ([#326](https://github.com/Jstar269/nakagawa-recomp/issues/326)), SIMD fast paths ([#292](https://github.com/Jstar269/nakagawa-recomp/issues/292)) and clean-room lineage replacement ([#347](https://github.com/Jstar269/nakagawa-recomp/issues/347)), are in the works. | [#40](https://github.com/Jstar269/nakagawa-recomp/issues/40), [#69](https://github.com/Jstar269/nakagawa-recomp/issues/69), [#292](https://github.com/Jstar269/nakagawa-recomp/issues/292), [#326](https://github.com/Jstar269/nakagawa-recomp/issues/326), [#347](https://github.com/Jstar269/nakagawa-recomp/issues/347) |
| Thread scheduler & Kernel synchronization | Works | Cooperative multi-threaded scheduler supporting threads, semaphores, mutexes, event flags, message boxes, and VBLANK wakeups. Hardware-measured thread attributes (CT/ST [#46]); deterministic liveness/starvation conformance workloads shipped ([#290](https://github.com/Jstar269/nakagawa-recomp/issues/290), done). Unregistered kernel object models ([#339](https://github.com/Jstar269/nakagawa-recomp/issues/339)) and the clean-room scheduler replacement spec ([#340](https://github.com/Jstar269/nakagawa-recomp/issues/340)) are in the works. | [#339](https://github.com/Jstar269/nakagawa-recomp/issues/339), [#340](https://github.com/Jstar269/nakagawa-recomp/issues/340) |
| Filesystem & Disc I/O (ISO9660, XB archives, VFS) | Partially works | Project-authored C ISO9660 PVD reader and directory-record walker (`src/player/iso_reader.c`, `nk_iso_extract_game`); project-authored XB archive extractor (`src/core/nk_xb.c`). Moving loose-disc layout rules out of generic HLE into validated title configuration ([#289]); archive-backed direct VFS to avoid tens of thousands of loose pre-extracted files ([#298]). | [#289](https://github.com/Jstar269/nakagawa-recomp/issues/289), [#298](https://github.com/Jstar269/nakagawa-recomp/issues/298) |
| Executable decryption & DRM (KIRK / PGD / amctrl) | Partially works | Automatically selects unencrypted `BOOT.BIN` or user-supplied plain `EBOOT.elf` in `<user data>/titles/<DISC_ID>/decrypted/`. The repository ships no decryption keys or tools; lawful KIRK decryption boundary under legal/provenance review ([#295]). PGD/amctrl review packet excluded from public tree. | [#295](https://github.com/Jstar269/nakagawa-recomp/issues/295) |
| Package building & Runtime launch (Native player) | Partially works | Native player discovers, validates, and launches generated v1 runtime packages from `<user data>/packages/<DISC_ID>/` and the display smoke fixture (`display-smoke-v1`). The library's **BUILD PACKAGE** button (or `tools/nk_cli.py build-package <disc_id>`) builds a package with live progress and cancel; a checkout without the private backends builds with the public backends automatically ([#473](https://github.com/Jstar269/nakagawa-recomp/pull/473)), and the owned-disc build/play route runs end to end in the player ([#487](https://github.com/Jstar269/nakagawa-recomp/pull/487)). A non-experimental catalog title with a resolvable developer runtime launches without a package ([#483](https://github.com/Jstar269/nakagawa-recomp/pull/483)). Automated one-click compile-and-launch directly from a raw ISO, with no local title manifest and no developer toolchain, is in the works ([#308](https://github.com/Jstar269/nakagawa-recomp/issues/308)). | [#296](https://github.com/Jstar269/nakagawa-recomp/issues/296), [#297](https://github.com/Jstar269/nakagawa-recomp/issues/297), [#308](https://github.com/Jstar269/nakagawa-recomp/issues/308) |
| Host platform support (OS) | Partially works | Windows 11 x64 fully supported with SDL3 and Vulkan. Linux host runtime/player support in progress after backend seams are portable ([#306]); macOS (Apple Silicon) planned ([#329]); Android ARM64 planned ([#360]). | [#306](https://github.com/Jstar269/nakagawa-recomp/issues/306), [#329](https://github.com/Jstar269/nakagawa-recomp/issues/329), [#360](https://github.com/Jstar269/nakagawa-recomp/issues/360) |
