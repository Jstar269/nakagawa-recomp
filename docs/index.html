Your PSP games, rebuilt as native PC programs.

Nakagawa Recomp is a static recompiler. It takes the program code of a PSP game you own and translates it, once and ahead of time, into a real Windows program. Nothing pretends to be a PSP while you play.

Windows 11 (64-bit) today; Linux, macOS and Android are planned. Free and open source under GPL-3.0-or-later. You bring your own game: none is included, and nothing here downloads one.

See it running

The two demos are PSP programs the project wrote itself, shown at the PSP's own 480×272. They contain no commercial game and run without any game files.

Why it is different

A PC program, not an emulator

An emulator imitates a PSP while the game runs. Nakagawa translates the game's code once, before you play, and builds it into a program your PC runs directly.

Honest when something is missing

If a game needs something that is not supported yet, the player stops and names the missing piece in a plain message. It never pretends that something worked.

Your game stays yours

No games, keys, firmware or system fonts are included or downloaded. The player is offline by default, uploads nothing built from your game, and has no telemetry.

Where things stand

Nakagawa Recomp is early, work-in-progress software. There is no release to download yet: the first one, v0.0.1, is being prepared and has no date. Until then the only way to try it is to build it from source, which the README walks through.

What works today

  • Drag in a disc image and the player reads the disc's own information to show the game's name and disc ID.
  • One button, Build package, recompiles the game with live progress and a cancel button, and turns on Play once the result checks out.
  • If build tools are missing, the player can fetch them after you agree once, showing each tool's version, size and licence first.
  • Controllers can be remapped and calibrated, with an optional mapping for each game.
  • Sound plays through your default audio device, video cutscenes play, and saves are kept in a local folder.

Not there yet

  • No download: building from source is the only route until v0.0.1 (#278).
  • Windows 11 only. Linux (#306), macOS (#329) and Android (#360) are planned.
  • Playing straight from a disc image with no setup is in the works (#308). Most retail games also need decrypted files from your own copy, as explained below.
  • No online or ad hoc play: networking is not implemented (#1139).
  • Some sound effects still fail to decode (#1096), and cutscene timing is not fully matched yet (#279).
  • The first release will not be code-signed, so Windows SmartScreen will warn the first time you run it.

Status as of October 2026. The full, always-current detail is in the compatibility list and the draft v0.0.1 release notes.

How it works

The same approach is behind Zelda 64: Recompiled (built with N64Recomp) and Unleashed Recompiled (built with XenonRecomp). Nakagawa brings it to the PlayStation Portable.

  1. Add your disc image

    Drag the .iso of a game you own into the player. It reads the disc's own information file to identify the game, and checks whether the game's program code is readable.

  2. Translate it, once

    The recompiler reads the game's program, written for the PSP's MIPS processor, finds its functions and translates each one into C source code. This happens before you play, not while you play.

  3. Build a PC program

    A C compiler turns that code, together with Nakagawa's runtime, into a native program. The runtime stands in for the PSP: its system software, graphics through Vulkan, and sound and controls through SDL3.

  4. Play, or get a straight answer

    Press Play. If the game reaches something Nakagawa does not support yet, it stops and names what is missing instead of guessing.

Curious about the details? Read the architecture overview and playing your own games.

Bring your own game

Here is what you need to play a PSP game with Nakagawa.

  • A Windows 11 PC (64-bit) with a graphics card that supports Vulkan, 8 GB of memory (16 GB recommended) and 5 GB of free disk space, ideally on an SSD.
  • Your own copy of the game, as an uncompressed .iso disc image. Whether you may make an image of a disc or of a digital purchase depends on where you live and on the terms you accepted, so check both.
  • Decrypted files from your own copy, for most retail games (see below).
  • Optional: the system fonts from your own PSP, for the console's original lettering. Without them, the project's own open fonts are used.

Public builds do not decrypt games

Most retail PSP games keep their program code encrypted. Public builds of Nakagawa do not decrypt games: they contain no decryption keys and never look for a key file.

Instead, you supply unencrypted copies of those files, made from your own copy of the game, in the folder the player shows on the game's card. If a file is still encrypted, the player names it and stops.

Laws on decrypting and copying games differ from country to country, so check the rules where you live. This is not legal advice. The guide to supplying unencrypted files shows what goes where.

Questions

Is this an emulator?

No. An emulator runs the original game code by imitating PSP hardware as you play. Nakagawa translates the game's code into a Windows program ahead of time, the way a PC port would be made.

Can I download it now?

Not yet. The first release, v0.0.1, is being prepared and has no date. You can follow it in issue #278, or build the player from source by following the README.

Will my favourite game work?

Probably not yet. One game is far along, one plays a stage, and the rest are untested. When you add a game, the player tells you what it still needs instead of guessing.

Does Nakagawa give me games, firmware or keys?

No. Nothing here includes or downloads games, firmware, keys or system fonts. You use your own copy of a game you own.

Does it go online?

Only if you agree. The player is offline by default; today the one exception is an optional download of build tools, which you approve first. Nothing built from your game is uploaded or shared, and there is no telemetry.

How is it made?

Nakagawa is developed with AI coding agents directed by the maintainer. Their work is treated like any other untrusted contribution: it must pass the same automated checks before it lands, and every commit made with AI help says so. The rules are in the AI usage policy.
